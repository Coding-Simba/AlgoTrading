# CR-001 — v0.3 / v0.4 registration and capital scaling target

**Status:** Draft, awaiting countersign  
**Issued:** 2026-05-10  
**Owner:** Director sponsor  
**Applies to:** Build Plan v1.4-r1; `configs/signoff_matrix.yml`; `configs/risk_limits.yml`; `configs/strategy_registry.jsonl`  
**Apply script:** `tools/cr_001_apply.py`

## 1. Summary

This CR proposes three coupled changes:

1. **Register** v0.3 (intraday mean-reversion to session VWAP) and v0.4
   (rule-based regime classifier + strategy-switch policy) in the strategy
   registry. Registration is performed **before** any v0.2 OOS query; this
   preserves the v0.2 OOS partition as clean validation data for v0.3 per
   §B.13.
2. **Add** v0.3 and v0.4 strategy specs as new appendices
   (`docs/appendices/B_strategy_spec_v0_3.md` and `B_strategy_spec_v0_4.md`).
   Skeleton implementation modules ship with this CR and remain inert behind
   their corresponding sign-off rows (`B_v0.3`, `B_v0.4`).
3. **Raise allocated capital** from $1,000 to $5,000 *conditionally* on the
   `paper` row in the sign-off matrix being signed. The capital raise is
   gated by the apply script — it does not take effect on CR countersign
   alone.

## 2. Motivation

### 2.1 §B.13 ordering window

§B.13 (canonical per errata §6) permits v0.3 to use the v0.2 OOS partition
as clean validation only if v0.3 rules were registered **before** the v0.2
OOS query ran. The v0.2 OOS query has not yet been run. Registering v0.3
now preserves the cleanest possible validation path. Failing to register
now forces v0.3 to either (a) wait for a fresh holdback partition or
(b) inherit a permanent contamination flag against the v0.2 OOS partition.
The work to draft v0.3 / v0.4 specs is independent of v0.2 implementation
progress, so the registration cost is small and the optionality preserved
is large.

### 2.2 Capital scale-up readiness

The current $1,000 allocation is calibrated for the framework / v0.2-only
program. After v0.2 + v0.3 (and the v0.4 switching layer) have demonstrated
a clean OOS pass and clean paper trading per §E.3, the per-trade unit
economics improve materially at higher allocations. Pre-authorizing the
capital raise as a CR — gated on `paper` sign-off — lets the program
transition without an additional CR cycle while still preserving Risk
Reviewer review at the gate.

## 5. v0.3 / v0.4 spec summaries

See `docs/appendices/B_strategy_spec_v0_3.md` and `B_strategy_spec_v0_4.md`
for full specs. Brief:

- **v0.3** — intraday mean-reversion to session VWAP. 5m bars, RTH only.
  Long when 5m close ≤ VWAP − 1.5×ATR(14), 60m trend is **not**
  short-aligned, signal-bar low > prior-bar low (stalling), and a wick
  rejection of ≥ 30% of the bar range is present. Mirror short. Stop at
  the 3-bar window extreme. Target = session VWAP at fill time. R-bounds
  identical to v0.2 (≥0.5×ATR, ≤1.5×ATR).
- **v0.4** — rule-based regime classifier (TREND / MEANREV / NEUTRAL),
  computed once per closed 60m RTH bar from realized vol, trend strength,
  and VWAP-deviation magnitude. Strategy-switch policy: TREND → v0.2 only;
  MEANREV → v0.3 only; NEUTRAL → no trades.

## 6. Risk-limits change (Phase A — paper-gate-conditional)

| Field                                       | Current | Proposed |
|---------------------------------------------|---------|----------|
| `allocated_capital_usd`                     | 1000    | 5000     |
| `daily_loss_limit_usd`                      | 90      | 450      |
| `max_oos_drawdown_pct`                      | 15      | 15       |
| `max_acceptable_losing_streak`              | 5       | 5        |
| `aggregate_program_drawdown_limit_pct`      | 20      | 20       |
| `risk_of_ruin_threshold_pct`                | 5       | 5        |

Rationale: the $-denominated daily loss limit is held at 9% of capital
(unchanged ratio); percent-based limits are unchanged. With $5,000
capital and $25 R, a 5-streak loss is $125 = 2.5% of capital, well below
the 20% aggregate ceiling. The Risk Reviewer is asked to verify the
arithmetic and contest if the unchanged percent caps are inappropriate at
the new capital level.

The apply script REFUSES to enact this change unless the `paper` row in
`signoff_matrix.yml` is signed.

## 7. Canonical registry path

This CR ratifies `configs/strategy_registry.jsonl` as the canonical path
for the strategy registry. The path is governance-tracked under this CR;
subsequent renames require a new CR. The registry is created on first
append.

## 8. Apply procedure

```
# Inspect intended changes (no writes):
python tools/cr_001_apply.py --step register-strategies --dry-run
python tools/cr_001_apply.py --step raise-capital --dry-run

# Enact registration (after countersigns are filled in this doc):
python tools/cr_001_apply.py --step register-strategies

# Enact capital raise (after the `paper` row is signed in signoff_matrix.yml):
python tools/cr_001_apply.py --step raise-capital
```

The script refuses with a clear, structured reason on any precondition
failure. It is idempotent: running it twice is a no-op on the second run.

## 9. Rollback

- **Registration is irrevocable** (the registry is append-only). A
  superseding entry can be added but the original record persists.
- **Capital change rollback:** a new CR proposing a return to $1,000
  values, countersigned per the same procedure.
- **Skeleton-code rollback:** removing `strategy_v03/` / `strategy_v04/`
  before registration is allowed; after registration the registry entries
  remain regardless of code state, and a new CR is required to mark the
  registered version as withdrawn.
